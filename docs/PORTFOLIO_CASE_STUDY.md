# MarketArc：从财经信息到可理解的判断框架

## 一句话介绍

面向非专业投资者的 AI 财经理解原型，解释事件、传导机制、预期差与失效条件，而不是告诉用户买什么。

## 问题与目标

用户可能知道降息、黄金或 AI 的新闻，但不知道中间如何影响资产，也容易把“利好”理解成必然上涨。产品希望帮助用户把逻辑讲给别人，并知道下一步观察哪些变量。这个目标尚未通过规模化用户研究验证。

## 三个关键取舍

1. **解释机制，而不是预测价格。** 产品宪法要求人话先于术语，反方必须指出传导被抵消的具体条件；不提供收益保证或交易指令。
2. **研究与表达分层。** ResearchContext 保留检索来源，ResearchBrief 提炼判断，Story A 解释因果，Story B 提供资产、预期与风险框架，最后通过 Schema 校验合并。代价是调用链变长，也产生阶段失败风险。
3. **等待可理解，失败可恢复。** 用户先读 Quick Take 和 Story A，刷新读取本地任务；B 失败时保留 A 并提供重试。它改善反馈，但不能替代模型端的可靠性。

## 工程实现

Next.js / React / TypeScript / Tailwind；Zod 校验模型输出；模型与搜索适配器分离；JSON 文件原子写入；响应式长文；本地缓存与有限重试；Playwright 离线流程和文字排版检查。

公开试用使用三个自带案例，避免演示依赖付费密钥。历史市场快照的公共链接进入相关教育机制示例，明确不是原始私人任务。测试用随机 ID 创建本轮临时数据，不能覆盖已有用户任务。

## 我的角色与 AI 协作

产品负责人主导定位、用户问题、质量标准、优先级，以及对 UI 字号、速度、权限同步和公开试用的反馈。AI 协助实现、诊断、文档和测试。展示时应能解释关键设计与代码，不把 AI 生成等同于自己完全手写，也不虚构上线用户量、转化率或业务收益。

## 验证边界

离线回归检查：输入校验、任务存储与刷新、Quick Take、Story A、完整故事、失败入口、体验码、三条市场链接、地图切换、四场景七视口排版。代码检查、构建和 Secret 扫描是独立检查。

这些检查不证明实时模型生成稳定、财经事实正确或内容达到专业分析师水平。历史 Human Calibration 约 70 分，只是当时的内容评估，不是本次重新测得的分数。当前真实生成仍可能数分钟等待、502、timeout 或 JSON validation failure。

## 下一步

先把模型响应与结构化输出稳定性变成可验证指标，再逐步改进信息密度、反方质量和术语解释。没有验证需求之前，不扩张会员、支付或复杂基础设施。

产品宪法与历史实验记录位于 [docs/marketarc](marketarc/PRODUCT_BRAIN.md)。历史记录用于解释演进过程，不是当前运行状态或质量保证。
